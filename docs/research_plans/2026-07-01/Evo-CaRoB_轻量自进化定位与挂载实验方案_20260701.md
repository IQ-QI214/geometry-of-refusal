# Evo-CaRoB 轻量自进化定位与挂载实验方案

> 日期: 2026-07-01  
> 状态: 研究方案 v1  
> 目标: 在不改变 CaRoB 主线、不扩成完整自动红队系统的前提下，引入轻量自进化和自动优化模块，增强 MoE 层定位与 LoRA/bridge 挂载决策。  
> 适用代码目录: `experiments/mibd_routing_v2/`  
> 核心结论: 自进化对象限定为 CaRoB 的结构配置，而不是底座 VLM、不是完整 agent 系统、也不是大规模自动 benchmark 生成。

---

## 1. 一句话方案

**Evo-CaRoB: Self-Evolving Locus and Mount Selection for Carrier-Routed Safety Repair**

在现有 CaRoB 中，sensor 层、gate 层、LoRA 挂载层、rank、阈值等关键结构配置主要依赖人工经验和单轮指标选择。Evo-CaRoB 将这些人工选择改造成一个轻量的、可审计的自进化配置搜索过程:

```text
上一轮实验结果
  -> LLM 提出候选配置
  -> 硬指标评估与审计
  -> archive 保存成功与失败轨迹
  -> 经验库提炼规则
  -> 下一轮候选配置
```

关键约束:

- LLM 只负责提出候选和归纳经验，不负责最终裁决。
- 任何候选进入下一轮，必须通过确定性指标或 held-out 行为评估。
- 自进化只发生在配置层面，不修改底座 VLM 参数，不让 agent 自改代码。
- 不引入完整自动红队系统，避免偏离当前 “VLM refusal routing failure + bridge repair” 主线。

---

## 2. 为什么不能做完整 AutoCaRoB

上一版构想中的完整 AutoCaRoB 包含自动红队、自动数据构造、自动训练、自动 benchmark 扩展和自动修复闭环。这个方向更完整，但会引入三个现实问题:

1. **工程量过大**  
   需要实现 multimodal red-team agent、策略库、图像生成/编辑器、judge 管线、训练数据管理、长期 archive 和安全沙箱。当前项目已经处于 v4 数据修复与 CaRoB 训练前夜，不适合大转向。

2. **主线会漂移**  
   研究问题会从 “sensor-gate routing failure 是否存在以及能否修复” 变成 “自动化安全评测系统是否有效”。这会弱化机制解释贡献。

3. **实验闭环过长**  
   完整自动红队需要大量在线查询和行为生成。我们当前更缺的是干净数据、严谨 probe audit、gate 定位和 bridge 上限验证。

因此，本方案采用最小可控升级:

> 不做完整自动红队，只做 **自动 locus/mount 选择**。  
> 不让 LLM 决定科学结论，只让 LLM 帮助探索配置空间。

## 3. 2026 顶会参考与可借鉴机制

### 3.1 ARMs, ICLR 2026 Poster

**论文**: ARMs: Adaptive Red-Teaming Agent against Multimodal Models with Plug-and-Play Attacks  
**链接**: https://openreview.net/forum?id=wQ4OykcxaV  
**可借鉴点**:

- 自动编排多模态攻击策略。
- 使用 layered memory 保存成功攻击轨迹。
- 使用 epsilon-greedy 在探索和利用之间平衡。
- Reviewer 重点关注 judge reliability、query budget、strategy vs orchestration ablation、cost-benefit breakdown。

**对本项目的启发**:

我们不复刻 ARMs 的红队系统，只借鉴其 “memory + feedback + budget-normalized search” 机制。Evo-CaRoB 的搜索对象不是攻击策略，而是 CaRoB 配置:

```text
ARMs: attack strategy search
Evo-CaRoB: sensor/gate/mount configuration search
```

### 3.2 DGM, ICLR 2026 Poster

**论文**: Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents  
**链接**: https://openreview.net/forum?id=pUpzQZTvGY  
**可借鉴点**:

- archive 保存多个历史 agent 变体，而不是只保留最优点。
- 从 archive 中选择 parent，生成下一代变体。
- 通过 empirical validation 决定是否保留新变体。
- 结果显示 self-improvement 与 open-ended exploration 都需要消融验证。

**对本项目的启发**:

Evo-CaRoB 不自改代码，但可以保留配置 archive:

```json
{
  "config_id": "gen02_cfg07",
  "sensor_layers": [4, 12, 20],
  "mount_layers": [24, 28],
  "rank": 4,
  "tau": 0.62,
  "metrics": {...},
  "parent_id": "gen01_cfg03"
}
```

这样可以证明 “配置搜索随代际改进”，而不是一次性人工调参。

### 3.3 HGM, ICLR 2026 Oral

**论文**: Huxley-Gödel Machine: Human-Level Coding Agent Development by an Approximation of the Optimal Self-Improving Machine  
**链接**: https://openreview.net/forum?id=T0EiEuhOOL  
**可借鉴点**:

- 当前性能不等于自改进潜力。
- 提出 clade / lineage 视角，用后代整体表现估计 parent 的长期价值。
- 强调对比 DGM、STOP、人类工程 agent，并补充 live benchmark 防止污染。

**对本项目的启发**:

Evo-CaRoB 的 parent selection 不应只选当前 score 最高的配置，还要考虑 lineage productivity:

```text
lineage_score(parent) =
  mean(top descendant scores)
  + improvement slope
  + diversity bonus
  - repeated failure penalty
```

这比 “取当前最优配置继续 mutation” 更像顶会级自进化设计。

### 3.4 EvolveR, ICML 2026

**论文**: From Interactions to Principles: Experience-Driven Self-Distillation for Evolving LLM Agents  
**链接**: https://icml.cc/virtual/2026/poster/65641  
**可借鉴点**:

- 将历史轨迹自蒸馏成可检索原则库。
- 区分 online interaction 与 offline self-distillation。
- 对原则做去重、合并、经验效用评分。

**对本项目的启发**:

Evo-CaRoB 保存两层经验:

1. raw trace: 完整实验配置、指标、失败样本、judge 输出。
2. distilled principle: 从 raw trace 中总结出的规则。

例如:

```text
原则: 若 layer0 held-out AUC 高但 cross-carrier transfer 不下降，优先判为视觉/source confound，而不是有效 sensor。
证据: v3 qwen3_vl_8b_probe_audit, v3 internvl3_8b_probe_audit。
```

### 3.5 Self-Evolving LLM Agents under Offline Data Support, ICML 2026

**链接**: https://icml.cc/virtual/2026/poster/62030  
**可借鉴点**:

- 用自动 process-reward labeling 解决稀疏延迟奖励。
- 使用 in-distribution critic，避免 policy improvement 走出数据支持。
- 强调 self-evolution 要受数据分布约束。

**对本项目的启发**:

Evo-CaRoB 的配置搜索也应受 “in-distribution” 限制:

- 不能搜索未抽取 hidden states 的层。
- 不能对 held-out benchmark 做适应性优化。
- 不能让 LLM 自由提出无法评估的配置。

### 3.6 Agent0-VL, ICML 2026

**论文**: Agent0-VL: Exploring Self-Evolving Agent for Tool-Integrated Vision-Language Reasoning  
**链接**: https://icml.cc/virtual/2026/poster/63095  
**可借鉴点**:

- VLM 自评估不能只靠文本 critique。
- 需要 tool-grounded verification。
- Solver/Verifier 双角色可以自反馈，但反馈必须有外部证据约束。

**对本项目的启发**:

我们的 LLM diagnoser 不能只读文字总结，必须读取工具产物:

- data audit JSON
- probe audit JSON
- hidden-state metrics
- image distribution stats
- judge ensemble outputs

### 3.7 EvoC2F, ICML 2026

**论文**: EvoC2F: Compiling Tool Orchestration for Efficient and Evolvable LLM Agents  
**链接**: https://icml.cc/virtual/2026/poster/63166  
**可借鉴点**:

- 经验库可能污染。
- learned skills 必须经过 verification-gated admission。
- 中间表示应结构化，避免自由文本计划不可验证。

**对本项目的启发**:

Evo-CaRoB 的候选配置必须是 JSON schema，不接受任意自然语言方案。经验库入库需要满足:

- 指标完整。
- 审计状态明确。
- 数据集、模型、seed 可追踪。
- 未通过审计的候选只能进入 failure archive，不进入 success archive。

### 3.8 Thought-Aligner, ICML 2026

**论文**: Think Twice Before You Act: Enhancing Agent Behavioral Safety with Thought Correction  
**链接**: https://arxiv.org/abs/2505.11063  
**可借鉴点**:

- 以轻量 plug-in 修正中间过程，而非修改底座 agent。
- 关注 unsafe trajectory 在执行前的中间状态修正。
- 强调低延迟、模型无关、可插拔。

**对本项目的启发**:

CaRoB 的 bridge/LoRA 也应强调轻量可插拔:

- 只挂少数层。
- 只在 gate 触发时激活。
- 不改底座 VLM。
- 良性输入尽量零扰动。

### 3.9 Agents Are Not Always Faithful Self-Evolvers

**链接**: https://arxiv.org/html/2601.22436v2  
**可借鉴点**:

- self-evolving agent 可能并不真正使用 condensed experience。
- raw experience 比 condensed summary 更容易被 agent 忠实利用。
- 需要通过 causal intervention 检查经验利用是否真实。

**对本项目的启发**:

必须做 memory faithfulness 消融:

- 无经验库。
- 只给 distilled principle。
- 只给 raw trace。
- raw trace + distilled principle。
- 打乱/替换经验后性能是否下降。

否则 “self-evolving” 只是一层包装。

## 5. 模块 A: Evo-Locus, 自进化 MoE 层定位

### 5.1 目标

自动选择 carrier-aware router 应读取哪些层，解决 “人工挑 layer 容易 cherry-pick” 的问题。

### 5.2 调用什么 AI

| 角色 | 推荐实现 | 是否参与裁决 | 目的 |
|---|---|---:|---|
| Proposal LLM | Qwen3-32B-Instruct / DeepSeek-R1-Distill / 开发期可用 Claude 或 GPT | 否 | 根据历史结果提出候选 layer set |
| Embedding model | BGE-M3 / E5-large | 否 | 检索相似历史配置和失败经验 |
| Scoring evaluator | 纯代码指标 | 是 | held-out AUC、transfer drop、permutation AUC、subspace gain |
| Optional surrogate | TPE / random forest / GP | 是, 但只作搜索器 | 预测候选配置性价比 |

最终论文建议用固定开源 LLM 复现实验，商业闭源 LLM 只用于开发探索，避免可复现性质疑。

### 5.3 输入

```json
{
  "model": "qwen3_vl_8b",
  "carriers": ["figstep", "typographic"],
  "available_layers": [0, 4, 8, 12, 16, 20, 24, 28, 32, 35],
  "probe_audit": {
    "within_heldout_auc": "...",
    "cross_carrier_auc": "...",
    "permutation_auc": "...",
    "transfer_drop": "..."
  },
  "subspace_report": "...",
  "data_audit": "...",
  "archive_retrieval": [
    "similar successful configs",
    "similar failure configs",
    "distilled principles"
  ],
  "budget": {
    "num_candidates": 20,
    "max_layers_per_candidate": 4
  }
}
```

### 5.4 输出

候选必须遵循固定 JSON schema:

```json
{
  "candidate_id": "gen02_locus_007",
  "sensor_layers": [4, 12, 20],
  "router_mode": "soft_topk",
  "topk": 3,
  "carrier_conditioned": true,
  "temperature": 1.0,
  "mutation_from": "gen01_locus_003",
  "rationale": "FigStep evidence peaks earlier while typographic remains mid-layer; include one early, one mid, one late layer."
}
```

### 5.5 候选生成策略

第一代不依赖 LLM，使用固定 seed candidates:

- top-1 AUC layer。
- top-3 AUC layers。
- max transfer-drop layers。
- early/mid/late 各一层。
- layer0-excluded top-k。
- per-carrier best layer set。

第二代开始使用 LLM + mutation:

- add layer。
- remove layer。
- shift layer to neighbor。
- switch soft/top1。
- change temperature。
- split carrier-specific layer sets。

### 5.6 评分函数

```text
score_locus =
  1.0 * mean_within_heldout_auc
  + 0.8 * positive_transfer_drop
  + 0.5 * subspace_gain
  + 0.5 * carrier_signature_separation
  - 1.0 * permutation_auc_excess
  - 1.0 * layer0_saturation_penalty
  - 0.2 * layer_count_penalty
```

解释:

- `positive_transfer_drop = within_auc - cross_carrier_auc`，用于奖励 carrier-specific re-encoding。
- `permutation_auc_excess = max(0, permutation_auc - 0.6)`，防止泄漏。
- `layer0_saturation_penalty` 专门惩罚 layer0 过早饱和。
- `layer_count_penalty` 防止 router 把所有层都纳入。

## 6. 模块 B: Evo-Mount, 自进化 LoRA/bridge 挂载层选择

### 6.1 目标

自动选择 bridge/LoRA 应该挂在哪些层，减少人工设定 gate_locus 和后段 LoRA 范围的任意性。

### 6.2 调用什么 AI

| 角色 | 推荐实现 | 是否参与裁决 | 目的 |
|---|---|---:|---|
| Proposal LLM | 同 Evo-Locus | 否 | 根据 gate effect 和 sensor-gate dissociation 提出挂载配置 |
| Target VLM | Qwen3-VL-8B / InternVL3-8B | 是 | 对 top-k 候选做真实行为生成 |
| Guard judge ensemble | Qwen3Guard + LlamaGuard + keyword/规则 | 是 | 标注 unsafe/refusal/over-refusal |
| Proxy evaluator | oracle bridge / hidden margin | 是 | 便宜筛掉明显差的 mount candidates |

### 6.3 输入

```json
{
  "selected_sensor_layers": [4, 12, 20],
  "gate_effect_by_layer": {
    "20": 0.12,
    "24": 0.41,
    "28": 0.73
  },
  "dissociation": {
    "figstep": {"angle": 71.3},
    "typographic": {"angle": 49.8}
  },
  "behavior_metrics": {
    "unsafe_despite_decodable_rate": 0.27,
    "over_refusal_rate": 0.08
  },
  "budget": {
    "num_proxy_candidates": 20,
    "num_short_train": 5
  }
}
```

### 6.4 输出

```json
{
  "candidate_id": "gen02_mount_004",
  "mount_layers": [24, 28],
  "bridge_type": "gated_lora",
  "rank": 4,
  "tau": 0.62,
  "alpha": 8.0,
  "nullspace_projection": true,
  "mutation_from": "gen01_mount_002",
  "rationale": "Layer 28 has strongest gate effect; layer 24 provides earlier correction with lower over-refusal risk."
}
```

### 6.5 Successive halving 流程

```text
20 个 mount candidates
  -> oracle bridge / hidden margin proxy
  -> 保留 top 5
  -> short LoRA training
  -> 保留 top 2
  -> full held-out behavior eval
```

### 6.6 评分函数

```text
score_mount =
  1.2 * risk_refusal_gain
  + 0.8 * unsafe_despite_decodable_reduction
  + 0.5 * heldout_carrier_generalization
  - 1.2 * over_refusal_delta
  - 0.8 * utility_drop
  - 0.3 * train_cost
```

硬闸门:

- `over_refusal_delta <= 5pp`
- `utility_drop` 不超过预设阈值
- Guard judge disagreement 高于阈值时进入人工抽样复核
- data/probe audit 未 clean 时禁止训练

## 7. 模块 C: Experience Memory, 原始轨迹 + 原则库

### 7.1 目标

让 “自进化” 不只是随机搜索，而是能利用历史经验，避免重复试错。

### 7.2 调用什么 AI

| 角色 | 推荐实现 | 目的 |
|---|---|---|
| Experience Distiller LLM | Qwen3-32B-Instruct / DeepSeek-R1-Distill | 从 raw trace 提炼原则 |
| Embedding model | BGE-M3 / E5-large | 相似经验检索 |
| Faithfulness checker | 纯实验干预 | 检查 LLM 是否真的使用经验 |

### 7.3 存储格式

每次运行后写入:

```json
{
  "run_id": "20260701_gen02_cfg07",
  "raw_trace": {
    "dataset": "phase2a_matched_v4",
    "model": "qwen3_vl_8b",
    "config": {...},
    "metrics": {...},
    "failure_cases": [...],
    "judge_outputs": [...],
    "audit_paths": [...]
  },
  "distilled_principles": [
    {
      "principle_id": "p_014",
      "type": "failure",
      "statement": "Layer0 saturation with high cross-carrier transfer is more likely visual/source confound than carrier-specific risk semantics.",
      "evidence_run_ids": ["v3_qwen_probe", "v3_internvl_probe"],
      "utility_score": 0.78
    }
  ]
}
```

### 7.4 经验入库标准

借鉴 EvoC2F 的 verification-gated admission:

- success archive: 必须通过 data audit、probe audit、held-out behavior eval。
- failure archive: 保存失败，但标注 failure type。
- principle library: 至少有 2 个 run 支持，或 1 个强证据 run + 人工确认。

### 7.5 经验忠实性测试

必须做以下消融:

| 设置 | 目的 |
---|---|
| no memory | 搜索器不读经验库 |
| raw only | 只给完整历史轨迹 |
| principle only | 只给 distilled principles |
| raw + principle | 完整经验 |
| shuffled memory | 打乱相关经验 |
| irrelevant memory | 替换成无关经验 |

判据:

- 如果 raw + principle 明显优于 no memory，说明经验有用。
- 如果 shuffled/irrelevant 不影响结果，说明 LLM 没真实使用经验，需要降级 self-evolving claim。

## 8. 模块 D: Auto-Audit, 自动诊断但不自动裁决

### 8.1 目标

自动生成每轮实验的 Go/No-Go 诊断报告，减少人工漏查混淆。

### 8.2 调用什么 AI

| 角色 | 推荐实现 | 是否裁决 | 目的 |
---|---|---:|---|
| Vision embedding model | CLIP / SigLIP / DINOv2 | 是, 作为统计工具 | safe/risk 图像分布距离 |
| LLM Diagnoser | Qwen3-32B-Instruct / Claude 开发期 | 否 | 将指标转成诊断报告 |
| Deterministic audit scripts | 现有 `run_data_audit.py`, `run_probe_audit.py` | 是 | Go/No-Go 闸门 |

### 8.3 输出

```json
{
  "verdict": "NO_GO",
  "failure_type": "visual_source_confound",
  "evidence": [
    "safe/risk pixel std ratio > 1.5",
    "carrier match rate < 0.99",
    "layer0 heldout AUC saturated",
    "cross-carrier transfer drop <= 0"
  ],
  "recommended_actions": [
    "rebuild safe pool with carrier matching",
    "increase neutral text density",
    "rerun pair-level split after metadata extraction"
  ]
}
```

### 8.4 与现有 v4 的关系

当前 v4 已经修复了 v3 暴露出的几个问题:

- safe 图尺寸对齐到 500x500。
- carrier 逐样本匹配。
- pixel std 从 v3 safe 约 27 提高到 v4 neutral pool 约 63，接近 v3 risk 参考约 73。
- hidden-state npz 新增 row metadata，支持 pair-level split。

Auto-Audit 的第一目标不是新功能，而是把这些人工审计流程标准化，确保后续每轮搜索都自动过闸门。

## 9. 端到端实验流程

### Round 0: v4 数据闸门

```text
build neutral safe pool
  -> build paired dataset v4
  -> run_data_audit
  -> clean 才允许抽 hidden states
```

### Round 1: hidden extraction + probe audit

```text
Qwen3-VL-8B / InternVL3-8B 抽 hidden states
  -> run_probe_audit
  -> pair-level split audit
  -> check saturation
```

### Round 2: Evo-Locus

```text
seed candidates
  -> cheap metric scoring
  -> archive update
  -> LLM 提出 gen2 candidates
  -> metric scoring
  -> select top-k sensor layer sets
```

### Round 3: Gate 定位

```text
forward-only gate search
  -> gate effect table
  -> detection-control angle
  -> unsafe despite decodable rate
```

### Round 4: Evo-Mount

```text
LLM proposes mount candidates
  -> oracle bridge proxy
  -> successive halving
  -> short LoRA top-k
  -> full behavior evaluation
```

### Round 5: Final eval

```text
Manual-CaRoB
Random Search
```

### 10.1 方法对照

### 11.1 必须有 budget-normalized 比较

## 14. 风险与降级方案

### 风险 1: LLM proposal 不优于随机搜索

降级:

- 主张改为 “verification-gated evolutionary search”，LLM 只是可选 proposer。
- 保留 TPE/随机 mutation 作为主搜索器。

### 风险 2: 自进化 archive 不带来提升

降级:

- 把 archive 改成 reproducibility 和 anti-cherry-pick 工具。
- 不强 claim self-evolving，只 claim automated configuration selection。

### 风险 3: Evo-Mount 训练成本过高

降级:

- 只做 oracle bridge proxy。
- LoRA 训练留作少量 top-2 配置验证。

### 风险 4: v4 数据仍有混淆

降级:

- 暂停 Evo-Mount。
- 只做 Auto-Audit 和数据修复，不训练。

## 15. 论文叙事建议

主线不改:

```text
VLM refusal routing failure:
模型能读出风险，但风险证据没有被路由到拒绝 gate。
```

方法升级:

```text
CaRoB:
carrier-aware sensor-to-gate bridge。

Evo-CaRoB:
用轻量自进化搜索自动决定 CaRoB 读哪里、挂哪里。
```

贡献写法:

1. 发现并量化 VLM 中 carrier-induced sensor-gate misrouting。
2. 提出 CaRoB，以动态 sensor-to-gate bridge 修复拒绝路由失败。
3. 提出 Evo-CaRoB，将 layer/mount 选择从人工启发式升级为 verification-gated self-evolving configuration search。

不要写:

- fully autonomous red-teaming system。
- self-improving VLM。
- recursive self-improvement。

这些会扩大 claim，也会引来更重的安全和工程质疑。

## 16. 最终推荐决策

建议采纳以下最小组合:

```text
必做:
  Evo-Locus
  Archive + deterministic scoring
  Auto-Audit report

强烈建议:
  Evo-Mount proxy
  Experience memory ablation

有时间再做:
  Short LoRA top-k training
  LLM proposal vs TPE full comparison
```

这样能满足三个目标:

1. **主线不变**: 仍然是 CaRoB 修复 VLM refusal routing failure。
2. **工程可控**: 大部分模块 CPU-only，优先复用已有 audit 输出。
3. **前沿感足够**: 与 2026 顶会的 auto/self-evolving 趋势对齐，但 claim 保守、可验证、可复现。
