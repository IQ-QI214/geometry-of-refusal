# VLM-Refusal:三个关键问题的澄清与方向升级

日期:2026-06-29
针对你提出的三个问题:(1) 三元组数据集来源与质量;(2) FigStep 在本工作中的真实角色;(3) 如何避免做成"简单老旧"的工作、接入最新前沿。

---

## 问题一:本地三元组数据集从哪来?AI 造数据质量低吗?

### 现状(来自代码 `HANDOFF.md`)
当前三元组 `(q, v^safe, v^risk)` 的构造**不是纯 AI 生成内容**,而是:

| 组成 | 来源 | 说明 |
|---|---|---|
| `v^risk`(风险视觉载体) | **MM-SafetyBench 真实图片** | `figstep` → `images_figstep`,`typographic` → `images_wr`,用真实图片路径,非生成 |
| `v^safe`(安全视觉对照) | 当前为 blank placeholder | **这是要补的短板**:正式实验应换成 matched benign 真实图 |
| `q`(文本请求) | benign-looking ambiguous prompt | 文本本身不直接 harmful,风险只来自视觉载体 |

### 关键澄清:为什么"AI 造数据质量低"在这里不构成主要威胁
三元组**不是用来训练模型生成内容**,而是作为**诊断探针(probe diagnostic)**。它的质量标准不是"语言流畅/内容真实",而是两条:

1. **配对纯净性**:同一 `q` 下,`v^safe` 与 `v^risk` 只在"是否含风险证据"上有差异 —— 这正是三元组设计的目的:**消除 dataset confound**(防止 probe 学到的是数据来源/文本风格而非风险本身)。
2. **标签正确性**:safe/risk 标签准确即可,不依赖生成质量。

因此真正的质量风险点是:**`v^safe` 目前用 blank 占位**,会让"安全对照"过于平凡(模型几乎一定区分得开),削弱诊断说服力。

### 建议(数据侧落地)
- risk 侧:保留 MM-SafetyBench 真实图 + FigStep 排版图(真实载体)。
- safe 侧:换成**主题匹配的真实 benign 图**(同场景、同物体类别但无风险),而非 blank。可从 MM-SafetyBench 的良性对照或公开 benign 图库取。
- 规模上先做 200 对 pilot 验证 schema 与可分性,再扩。

> 一句话:你们的数据不是"AI 编故事",是"用真实风险载体做配对对照实验",质量取决于配对控制而非生成质量;唯一要补的是把 safe 侧的 blank 换成真实 matched benign 图。

## 问题二:FigStep 在这里到底是什么角色?

你的判断是对的:**FigStep(arXiv:2311.05608)是一个越狱攻击算法**(把有害文本转成排版图像),**不是 benchmark,也不是你的核心参考方法**。

### 它在本工作中的正确定位:一个"受控的极端视觉载体刺激条件"
FigStep 在这里既不是数据集也不是方法,而是**视觉载体谱系中的一个极端 stimulus condition**,与 V-text / V-blank / V-noise / V-real 并列。它的价值只有一个:**制造载体差异最大的极端 case,用来暴露风险证据的重定位现象**。

证据就在你已有的 Phase 1 数据里:

| 发现 | 数据 | 说明 |
|---|---|---|
| best layer 大幅前移 | Qwen3-VL 15→1,InternVL3 6→0 | FigStep 让风险证据的最佳可读位置跳到极早层 |
| 方向几乎正交 | cos(FigStep, V-text)=0.259 / 0.136 | FigStep 用的是**不同方向**的 harmfulness 编码 |

这正是你最锋利的一张牌:它**反驳了"同方向、只是幅度收缩"**的假设(ReGap 的 Safety Geometry Collapse、OmniSteer 的 modal-invariant pure direction 都建立在这个假设上)。

### 建议(叙事侧落地)
- 把 FigStep **降格**为"载体谱系中的一个极端点",不要让它喧宾夺主,更不要把它写成核心参考工作。
- motivation 里这样用:"我们用从自然图(V-real)到排版图(FigStep)的**载体谱系**,证明风险证据的可读位置与方向随载体系统性迁移。"
- 引用层级:FigStep 仅作为"视觉载体会改变安全行为"的现象级引用,不进核心方法对标。

## 问题三:工作是不是太简单太旧?如何接入最新前沿

这是最重要的问题。调研结论很直接:**你原本"refusal vector + sensor-gate + 动态 bridge"的框架在 2025 年是新的,但 2026 年上半年已经有多篇工作冲进同一战场。若不升级叙事和方法,确实有"做旧"风险。** 但同时也存在清晰的生存缝隙。

### 3.1 撞车地图(必须正面处理,按危险度排序)

| 工作 | 编号/出处 | 与你撞在哪 | 关键区别(你的缝隙) |
|---|---|---|---|
| **DSH: Knowing without Acting** | 2603.05773 | Recognition Axis vs Execution Axis,"知道但不行动"—— 与你 sensor-gate 几乎同名 | **LLM-only + 用于攻击**;它假设轴在深层稳定,你证明 VLM 中随视觉载体重定位;它攻击,你防御修复 |
| **Low-Resource Failures Are Action Failures** | 2606.01196 | "拒答失败是 action 失败不是 representation 失败",harmfulness 仍线性可分但拒答率掉一半 | **纯文本低资源语言**;你是视觉模态;它用少样本重校准,你用动态 bridge |
| **DBDI** | 2511.06852, AAAI 2026 | Detection 方向 vs Execution 方向二分 | LLM-only + 攻击 |
| **Perfect Detection, Failed Control** | 2606.24952 | detection 方向 ≠ control 方向,夹角 83°(cos≈0.12) | LLM-only;**它给了你现成的量化工具**(detection-control gap),可直接搬到 VLM |
| **ReGap / Safety Geometry Collapse** | 2605.18104 | VLM、training-free、输入依赖 self-rectification | 它归因"几何坍塌→证据被压缩";你归因"证据可读但未路由";它用单一聚合 drift 方向(自承短板),你用多 locus |
| **MoRAS: Attention Misses Visual Risk** | 2510.13698 | VLM、risk-adaptive steering、标题几乎撞名 | 它归因"注意力没看到风险"(感知缺陷);你归因"看到了但没路由到 gate"—— **正好相反,可设为对立假设靶子** |
| **OmniSteer / Omni-Safety** | 2602.10161 | refusal vector + 自适应强度 adapter | 它主张"modal-invariant pure direction"(同方向);你的 cos=0.259 直接反证 |

### 3.2 你真正的护城河(三句话)
1. **模态**:上面所有 sensor-gate 解离工作(DSH/DBDI/Action-failure/Perfect-Detection)**全是 LLM 纯文本**,且都假设方向/轴稳定;你是 **VLM,且证据随视觉载体换层换方向重编码** —— 这是首次在多模态揭示该解离的动态性。
2. **方向(攻击 vs 防御)**:它们用解离做**攻击**;你用解离做**防御性 causal bridge 修复**。
3. **闭环**:现有工作(含 ICML'26 的 SALO、Robust Harmful Features)**止步于"读取/检测"持久信号**,几乎无人做"把迁移后的证据**因果搬回行为控制点**以恢复拒答"。这是你 oracle bridge 的空白,也是唯一的硬创新 —— **Go/No-Go 实验(oracle bridge 显著优于 ReGap-style drift correction)必须立住**。

### 3.3 升级路线(让工作"新"起来的具体动作)

**路线 A:重命名问题框架(低成本,高收益)**
把叙事从"refusal vector 迁移"升级为"**拒答路由失败(refusal routing / action failure)**",主动对齐 2026 新框架(2606.01196 的 action vs representation、MoE 路由系列)。把自己定位成 **2606.04778 / 2606.24952"内部对齐度 ≠ 行为安全"结论在多模态的首个机制级验证**。

**路线 B:方法工具升级(中成本)**
| 旧做法 | 升级为 | 依据 |
|---|---|---|
| 单一 refusal direction | 多方向子空间(INLP / Diff-in-Means 对比) | 2606.13720 Refusal Beyond a Single Direction |
| 主观判断 sensor≠gate | detection-control 夹角量化(cos / 角度) | 2606.24952 给的现成指标 |
| 梯度/attribution 定位 gate | **前向对比筛选**(forward-only) | 2606.19831:梯度归因会反预测控制力,会失效 |
| ad-hoc locus 选择 | SAE 定位 + causal patching + clamping | PSF-Med 2602.21428 模板;Vision-Default 2606.28273 的 routing/writing head 二分 |

**路线 C:多模态专属新增贡献(高收益,目前空白)**
- **视觉 persona / 视觉 context 是否门控拒答路由**(类比文本 persona 门控 2606.26161)—— 当前无人做 VLM 版,是干净的增量。
- **think-with-image 安全残差偏移**(2605.27932)在 VLM 路由失败中的作用 —— 把工作接到 2026 最热的"推理型多模态安全"。
- **评测升级**:加入跨模态组合风险(单模态无害、组合有害,2606.22873 / 2606.01837)、轨迹级注入鲁棒性(2606.04778),不只静态拒答率。

### 3.4 一页纸的升级后定位(可直接写进 motivation)
> 此前"知道但不拒答(knowing without acting)"的安全解离仅在 **LLM 纯文本域**被观察,且被用于**构造攻击**,并默认安全轴在深层稳定。我们首次在 **VLM** 中揭示:风险证据虽在隐藏态高度可读,但其**可读位置与方向随视觉载体动态重编码**,导致固定方向 / 全局 drift correction 无法将其因果路由到下游安全行为 gate。我们提出**动态多 locus 的证据-到-策略桥(oracle bridge)**,首次将这一解离用于**防御性行为修复**,并证明其显著优于 ReGap 式 drift correction 与 MoRAS 式注意力增强。

## 落到现有代码的最小调整清单
1. `run_build_phase2a_dataset.py`:把 safe 侧 blank 换成 matched benign 真实图(问题一)。
2. `probes/`:增加多方向子空间 probe(INLP),并输出 detection-control 夹角(路线 B)。
3. `behavior/gate_search.py`:gate 定位改用前向对比筛选,不依赖梯度(路线 B)。
4. `bridge/oracle_bridge.py`:对标基线补齐 ReGap-style drift correction + MoRAS-style attention steering,Go/No-Go 必须打赢这两个(护城河第 3 点)。
5. 评测集:新增"单模态无害-组合有害"与轨迹注入样本(路线 C)。
