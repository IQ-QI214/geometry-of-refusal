## 0. 一页纸总览

**研究问题(升级后)**:在 VLM 中,风险证据虽在隐藏态高度可读,但其**可读位置与方向随视觉载体动态重编码**,导致它没有被因果路由到下游安全行为 gate —— 这是一种**多模态拒答路由失败(refusal routing failure)**,而非感知失败,也非单纯几何坍塌。

**三句话护城河**:
1. 现有 sensor-gate 解离工作(DSH 2603.05773、DBDI、Perfect-Detection 2606.24952、Action-failure 2606.01196)**全是 LLM 纯文本**且假设方向稳定;我们是 **VLM + 载体依赖的动态重编码**。
2. 它们用解离做**攻击**;我们用解离做**防御性 causal bridge 修复**。
3. 现有工作止步于"读取/检测";我们做**把迁移后的证据因果搬回行为控制点恢复拒答**的闭环。

**落地主线**:数据(配对纯净)→ 传感器(多 locus、多方向)→ 解离量化(detection-control 夹角)→ 行为标注 → gate 定位(前向筛选)→ oracle bridge → 打赢 ReGap / MoRAS 基线。

## 1. 研究问题(升级后表述)

给定 VLM $M$ 与多模态输入 $x=(q,v)$,在每个 layer-position 位置 $(\ell,p)$ 产生隐藏态 $h_{\ell,p}(x)$。区分两个对象:

- **安全传感器(sensor)**:哪些 $(\ell,p)$ 能线性读出"输入是否含风险证据"。
- **行为门控(gate)**:干预哪些 $(\ell,p)$ 会因果改变模型的安全策略行为。

核心问题:**sensor 与 gate 是否解离,且这种解离是否被视觉载体动态放大;若是,能否通过动态桥接把 sensor 证据因果送进 gate 来修复拒答行为。**

(相比 6 月初旧表述,关键升级是把"refusal vector 迁移"重命名为"拒答路由失败",主动对齐 2026 的 action-vs-representation 框架。)

## 2. 研究假设(三条,逐条对应实验)

| 假设 | 内容 | 验证实验 | 对应代码 |
|---|---|---|---|
| **H1 可读性** | 风险证据在多种视觉载体下高度可读(probe AUC 高),且最佳 locus/方向随载体迁移 | 多 locus probe + relocation 量化 | `probes/evaluate_sensor.py`(已有 `evaluate_multi_locus_readout`/`compute_relocation_scores`) |
| **H2 解离** | sensor 的最佳可读位置 ≠ 控制拒答行为的因果位置;且证据可读时行为仍可能不安全 | detection-control 夹角 + "可读但不安全率" | `behavior/routing_metrics.py`(已有 `unsafe_despite_decodable_rate`)+ 新增夹角度量 |
| **H3 可修复** | 把动态多 locus 证据桥接进 gate,可显著提升风险样本拒答率,且不破坏良性样本 | oracle bridge vs ReGap/MoRAS/固定方向基线 | `bridge/oracle_bridge.py` + `baselines/*` |

## 3. 研究方法:三阶段管线(选层 → 搬运 → 门控)

这仍是**一个方法的三个环节**,不是三个并列方法。每个环节我标注了"旧做法 → 升级做法(依据)"。

### 环节①:选层 / 多 locus 传感(Router)
- 旧:在单层取一条 refusal 方向。
- **升级**:多 locus 读取 + **多方向子空间**(不是一条线,而是一个低维子空间)。依据:`Refusal Beyond a Single Direction`(2606.13720)、`SALO Refusal Trajectory`(ICML'26)。
- 产物:每个 $(\ell,p)$ 的风险得分 + 跨 locus 聚合得分(`evaluate_multi_locus_readout` 已实现聚合)。

### 环节②:解离量化(Dissociation Metric)
- 旧:主观判断"sensor≠gate"。
- **升级**:用 **detection 方向与 control 方向的夹角(cosine/角度)** 做硬量化。依据:`Perfect Detection, Failed Control`(2606.24952,LLM 上夹角达 83°)。这是把 H2 钉死的关键数字。
- 产物:每个载体条件下的 detection-control 夹角表。

### 环节③:门控修复(Gate + Transport Bridge)
- 旧:固定方向 steering / 梯度归因找干预点。
- **升级**:
  - gate 定位改用**前向对比筛选**(forward-only),不用梯度。依据:`Leverage Is Not Reach`(2606.19831,梯度归因会反预测控制力)。
  - 搬运用 **oracle dynamic bridge**(输入依赖、多 locus 加权),先验证上限,不训练。`bridge/oracle_bridge.py` 已实现。
- 产物:bridge 后风险样本拒答率提升、良性过拒增量。

## 4. 输入与输出(自然语言形式化)

| 阶段 | 输入 | 输出 |
|---|---|---|
| 数据构建 | MM-SafetyBench 真实风险图 + 主题匹配真实 benign 图 + 中性文本 | 配对三元组 `(q, v^safe, v^risk)` JSONL |
| 传感器 | 模型在各 locus 的隐藏态 + safe/risk 标签 | 各 locus AUC、聚合 AUC、最佳 locus、relocation 分数 |
| 解离 | detection 方向、control 方向 | 夹角表 + "可读但不安全率" |
| 行为标注 | 模型对 safe/risk 图的生成文本 | 行为标签(safe_policy / unsafe_compliance / over_refusal / ...) |
| gate 定位 | 干预前后的安全策略 margin | 每个 locus 的 gate_effect |
| bridge | gate 隐藏态 + 各 locus 证据 | 修复后隐藏态 → 行为变化 |

## 5. 落到现有代码:模块级改造清单

> 标记说明:🟢=传参即可(不改码) / 🟡=小改现有文件 / 🔴=新增文件 / [CPU]/[GPU]=运行环境

### 5.1 数据层 `data/`(对应问题一:safe 图换真实图)

**5.1.1 🟢 [CPU] 立即可做:换 safe 侧真实图(无需改代码)**
`run_build_phase2a_dataset.py` 已有 `--safe-image-dir`,`convert_phase2a._collect_safe_images` 已支持真实图池。只需准备一个真实 benign 图目录传进去:
```bash
python -m experiments.mibd_routing.run_build_phase2a_dataset \
  --mmsafety-dir <MM-SafetyBench 路径> \
  --safe-image-dir <真实benign图目录> \
  --output-dir results/mibd_routing/paired_dataset/phase2a_real_v2 \
  --num-pairs 200 --seed 20260604
```
效果:`_safe_image_for_pair` 会从真实池取图,`safe_image_mode` 标为 `safe_image_pool`,不再是 blank。

**5.1.2 🟡 [CPU] 升级为"主题匹配"配对(改 `convert_phase2a.py`)**
现状:`_safe_image_for_pair` 用 `index % len` **随机**取 safe 图,与 risk 图的 `category` 无关 → 配对不够"matched"。
改法:把 safe 图池按类目组织,按 `item.category` 选同类 benign 图。
- 改 `_collect_safe_images`:返回 `dict[category, list[path]]`(按子目录名归类),而非扁平 list。
- 改 `_safe_image_for_pair`:新增 `category` 入参,优先从同类取,缺类回退全局池。
- `build_phase2a_paired_dataset` 调用处把 `item.category` 传进去。
为什么:配对纯净性是三元组消除 dataset confound 的根本(见前沿对标问题一)。

**5.1.3 🟡 [CPU] 新增"组合风险"载体(可选,接前沿评测)**
在 `schema.CarrierType` 已有枚举基础上,新增一类"单模态无害-组合有害"样本(文本无害+图无害,但组合后有害)。依据:`SingGuard`(2606.22873)、`DSR`(2606.01837)。这是评测升级,非必需,建议二期。

### 5.2 探针层 `probes/`(环节①+②)

**5.2.1 🟡 [CPU,基于已抽取的 hidden] 多方向子空间 probe**
现状:`evaluate_sensor.py` 做单方向/多 locus AUC 聚合。
新增:在该文件加一个 `evaluate_subspace_readout(...)`,用 INLP 或多次 Diff-in-Means 提取风险子空间(秩 k=2~4),输出子空间 AUC 与单方向 AUC 的增益。
为什么:`Refusal Beyond a Single Direction`(2606.13720)证明拒答需多方向子空间;避免被"单向量叙事"做旧。

**5.2.2 🔴 [CPU] 新增 detection-control 夹角度量(`probes/dissociation.py`)**
新建文件,实现:
```
detection_direction = Diff-in-Means(risk_hidden, safe_hidden)   # 从 sensor 端取
control_direction   = 从 gate_search 得到的最有效干预方向       # 从 gate 端取
angle = arccos(cosine(detection_direction, control_direction))
```
输出:每个载体条件下的夹角。这是 H2 的核心数字(目标:显著大于 0°,理想接近 LLM 上观察到的 ~83°)。依据:`Perfect Detection, Failed Control`(2606.24952)。

### 5.3 行为层 `behavior/`(环节③ gate 定位)

**5.3.1 🟡 [GPU] 真实行为生成与标注**
现状:`label_outputs.py` 是规则标注(冒烟测试用),`vlm_generators.py`/`generate_outputs.py` 是生成入口。
改法:GPU 上用真实模型生成 safe/risk 输出 → 用 LlamaGuard3/Qwen3Guard 做 judge 标注(替代规则),写回 `behavior_label`。规则标注仅留作 CI 冒烟。
为什么:`routing_metrics.compute_routing_failure_metrics` 依赖准确的 `behavior_label` 才能算"可读但不安全率"。

**5.3.2 🟡 [GPU] gate 定位改前向对比筛选**
现状:`gate_search.py` 有 `safe_policy_margin`/`gate_effect`(逐 locus 干预后看 margin 变化)。
改法:保持 `gate_effect` 的"前向干预看 margin"逻辑(这本身就是 forward-only,正确方向),**显式避免引入任何梯度/attribution 排序**。新增一个 `rank_gate_loci(...)`:对候选 locus 批量做 activation patching,按 `gate_effect` 排序输出 top-k gate。
为什么:`Leverage Is Not Reach`(2606.19831)证明梯度归因会反预测控制力,前向对比才可靠。

### 5.4 基线层 `baselines/`(H3 必须打赢的对手)

**5.4.1 🟢 已有,直接用**:`fixed_direction.py`(固定 DIM)、`opd.py`(正交子空间)、`regap_style.py`(全局 drift correction)。

**5.4.2 🔴 [CPU/GPU] 新增 MoRAS-style 注意力增强基线(`baselines/moras_style.py`)**
依据:`MoRAS`(2510.13698)归因"注意力没看到风险",是你的**对立假设靶子**。必须把它做成基线,证明"光增强视觉注意力"不如"把可读证据路由到 gate"。
最小实现:对 safety-critical 视觉 token 上调注意力权重后再生成,记录拒答率,与 oracle bridge 对比。

### 5.5 桥接层 `bridge/`(环节③ 搬运)

**5.5.1 🟢 已有**:`oracle_bridge.py` 的 `apply_oracle_bridge(gate_hidden, evidence_by_locus, config)` 已实现多 locus 加权聚合 + 可选 bridge_matrix。
**5.5.2 🟡 [GPU] 接线**:写一个驱动脚本,把 5.2 的多 locus 证据 + 5.3 定位的 gate locus 喂进 `apply_oracle_bridge`,在前向中替换 gate 隐藏态,生成并标注,统计修复效果。先做 oracle(不训练),验证 H3 上限。

### 5.6 报告层 `reports/`

**5.6.1 🟡 [CPU] 扩展 `make_phase2_report.py`**:汇总三张核心表 —— (a) 多 locus/子空间 AUC + relocation;(b) detection-control 夹角 + 可读但不安全率;(c) bridge vs 各基线的拒答提升/过拒增量。直接产出可贴飞书的 Markdown。

## 8. 验收标准(Go/No-Go,沿用 meeting brief 并量化)

| 指标 | 阈值 | 说明 |
|---|---|---|
| 多 locus 子空间 held-out AUC | ≥ 0.85 | H1 可读性成立 |
| detection-control 夹角 | 显著 > 0(目标接近 LLM 的 ~83°) | H2 解离成立 |
| "风险可读但不安全"样本占比 | ≥ 15% | 证明路由失败真实存在 |
| oracle bridge 风险拒答提升 | ≥ +10pp,且显著高于 ReGap/MoRAS | H3 可修复 + 打赢撞车基线 |
| 良性过拒增量 | ≤ +5pp | 不破坏可用性 |
| degeneration 增量 | ≤ 0 | 不损生成质量 |

任一硬指标不达标 → 回到对应环节,不进入 learnable bridge 训练阶段。
