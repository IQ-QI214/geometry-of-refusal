# 交接文档：从验证闸门切到方法推进优先

> 面向：新窗口 / 新 agent  
> 适用仓库：`geometry-of-refusal`  
> 当前主线：CaRoB / Evo-CaRoB, `experiments/mibd_routing_v2/`  
> 核心要求：**不要继续陷入“验证性实验无限前置”的循环。先做一版方法，跑出结果，再用结果改方法。**

---

## 0. 一句话决策

从现在开始，研究推进策略改为：

```text
最小必要审计防止明显假信号
  -> 立刻跑 Method MVP
  -> 用结果诊断方法问题
  -> 再迭代数据、层选择、挂载点和训练配方
```

也就是说，审计不再是“所有科学动机完全成立才允许写方法”的前置条件；审计只拦截**明显会让实验无意义的硬错误**。其余问题进入 limitation / diagnostic report，不阻塞方法实验。

## 2. 新的闸门政策：Hard Gate vs Diagnostic Gate

### 2.1 Hard Gate：不通过就不能进入 GPU 方法实验

这些是“跑了也没意义”的错误，必须拦：

| Hard Gate | 判据 |
|---|---|
| 数据结构错误 | pair integrity 失败、safe/risk 不平衡 |
| 明显视觉混淆 | carrier match < 0.99、safe/risk size 不一致、pixel std ratio > 1.5 |
| 元数据缺失 | 新抽取的 npz 没有 `row_metadata_json` |
| 评测器坏了 | permutation held-out AUC 明显高于 0.6 |
| 代码不可运行 | 相关 pytest / torch parity 失败 |

### 2.2 Diagnostic Gate：记录，不阻塞

这些是科学信号强弱问题，不应无限阻塞：

| Diagnostic | 原处理 | 新处理 |
|---|---|---|
| cross-carrier transfer drop <= 0 | 回去继续修数据 | 记录为 “carrier-specific re-encoding weak”，仍跑 Method MVP |
| layer0 AUC 偏高但 permutation 正常 | 停止 | 标记为 “early visual feature risk”，做 layer0-excluded ablation |
| within held-out AUC 很高 | 停止 | 作为 sensor 可读性强的条件，进入方法实验 |
| v4 仍不完美 | 继续打磨 | 时间盒内不再阻塞，写 limitation |

**原则**：Hard Gate 保障实验不是垃圾；Diagnostic Gate 用来解释结果，不再阻断方法推进。

## 3. 立即要做的方法 MVP

先做 **Evo-Locus CPU-only Method MVP**，因为它：

- 不需要新 GPU；
- 直接复用已有 audit JSON / hidden npz；
- 是 Evo-CaRoB 的方法核心之一；
- 能把项目从“验证数据”推进到“方法对照实验”。

### 3.1 MVP 目标

实现一个可复现的配置搜索方法，自动选择 CaRoB 的 sensor layer set，并和人工/随机基线比较。

```text
输入：probe audit / data audit / available layers
输出：candidate layer sets + score + archive
对照：Manual-CaRoB, Random Search, Evo-Locus(seed + mutation)
```

### 3.2 不是现在做的事

第一版不要做完整 LLM agent，不要做完整 LoRA 训练，不要做自动红队。

暂不做：

- multimodal red-team agent；
- LLM 自改代码；
- 完整 Evo-Mount 训练；
- 竞品 SafeSteer/SafeCoDe 全评测；
- SafetyPairs/SIUO 全接入。

这些都可以后续迭代。

### 4.1 `schema.py`

定义结构化配置，不接受自由文本：

```python
@dataclass(frozen=True)
class LocusCandidate:
    candidate_id: str
    sensor_layers: tuple[int, ...]
    router_mode: str = "soft_topk"
    topk: int = 3
    carrier_conditioned: bool = True
    temperature: float = 1.0
    parent_id: str | None = None
    rationale: str = ""
```

```python
@dataclass(frozen=True)
class LocusMetrics:
    mean_within_heldout_auc: float
    mean_cross_carrier_auc: float
    mean_permutation_heldout_auc: float
    transfer_drop: float
    layer0_included: bool
    layer_count: int
```

### 4.2 `scoring.py`

实现确定性评分函数。第一版先用文档里的简化版：

```text
score_locus =
  1.0 * mean_within_heldout_auc
  + 0.8 * max(0, transfer_drop)
  - 1.0 * max(0, permutation_auc - 0.6)
  - 0.5 * layer0_penalty
  - 0.05 * layer_count
```

注意：如果 `transfer_drop <= 0`，不要让方法直接失败，只是不加分。

### 4.3 `mutations.py`

第一版只做 deterministic mutations：

- add nearest layer；
- remove one layer；
- shift layer to neighbor；
- exclude layer0；
- per-carrier best union；
- early/mid/late 三段各取一个。

### 4.4 `archive.py`

写 JSONL archive：

```json
{
  "run_id": "20260702_evo_locus_v0",
  "candidate": {...},
  "metrics": {...},
  "score": 0.73,
  "status": "accepted|rejected|diagnostic",
  "notes": ["transfer_drop<=0, method still evaluated"]
}
```

### 4.5 `run_evo_locus.py`

命令行：

```bash
python -m experiments.mibd_routing_v2.evo.run_evo_locus \
  --probe-audit results/mibd_routing_v2/runs/20260630_125933_phase2a_v3_dual_model/offline_oracle/qwen3_vl_8b_v3_probe_audit.json \
  --out-dir results/mibd_routing_v2/evo/20260702_evo_locus_v0 \
  --model qwen3_vl_8b \
  --max-layers 4 \
  --seed 20260702
```

输出：

```text
results/mibd_routing_v2/evo/20260702_evo_locus_v0/
  candidates.jsonl
  archive.jsonl
  scoring_report.json
  README.md
```

## 5. 实验对照

第一版至少输出这三组：

| 方法 | 定义 | 目的 |
|---|---|---|
| Manual-CaRoB | 人工规则：top held-out AUC layer / top-k layers | 当前人工基线 |
| Random Search | 同等候选预算随机采样 layer set | 排除只是搜索预算带来的收益 |
| Evo-Locus v0 | seed candidates + deterministic mutations + scoring | 第一版方法 |

如果 v3/v4 signal 不理想，也照样比较。结果不好也有价值：说明方法在当前信号下无法优于随机，下一步改 scoring / 数据 / 挂载。

## 6. GPU 队列可用后怎么接

GPU 可用时，不要重新回到无限验证。执行顺序：

1. `git pull`
2. 如已有 v4 图池，直接用：
   `data/mibd_routing_v2/benign_safe_images_v4/`
3. 重建 v4 dataset：

```bash
python -m experiments.mibd_routing_v2.run_build_phase2a_dataset \
  --mmsafety-dir /inspire/hdd/global_user/wenming-253108090054/czk/MML/dataset/mm-safebench \
  --safe-image-dir data/mibd_routing_v2/benign_safe_images_v4 \
  --output-dir results/mibd_routing_v2/paired_dataset/phase2a_matched_v4 \
  --num-pairs 200 \
  --seed 20260604
```

4. 跑 `run_data_audit`。如果 Hard Gate clean，继续；如果只是不满足 Diagnostic 信号，不阻塞。
5. 抽 hidden states。
6. 跑 `run_probe_audit`。
7. 用新 audit JSON 再跑 `run_evo_locus.py`。

## 7. 成功标准

### 7.1 工程成功标准

- `pytest` 覆盖 schema/scoring/archive。
- `run_evo_locus.py` 能读 v3 probe audit 并输出完整 archive。
- 结果目录有 README，总结 top candidates 和失败原因。

### 7.2 研究成功标准

第一版不要求显著超过所有 baseline。最低要求：

- 能把 layer 选择从人工规则转成可复现搜索；
- 能解释每个候选为什么得分高/低；
- 能保留失败配置，避免 cherry-pick；
- 能为下一步 Evo-Mount / LoRA 训练提供 top-k sensor layers。

### 7.3 不要等待的东西

不要等待：

- 完美 cross-carrier transfer drop；
- 完美 SafetyPairs 数据；
- 完整 behavior eval；
- 完整 LoRA 训练；
- LLM proposal 接入。

这些都是后续迭代，不是 Method MVP 的前置依赖。


